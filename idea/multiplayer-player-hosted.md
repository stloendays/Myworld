# 创意 04｜玩家自建房间与私人联机（Player-hosted Co-op）

> **决策记录：2026-10-21**  
> **产品要求：计划将此功能作为未来面向朋友发布的 Windows 安装包的内置功能，而不是另行下载的联机扩展包。**  
> **实现状态：未开发、未验证、尚未提供安装包。** 本文属于 `idea/` 创意规划，不改变当前单机 MVP 的已完成状态；确定研发排期后应同步更新 [正式规格](../docs/DEVELOPMENT_SPEC.md)。

## 1. 希望玩家体验到什么

- **每个玩家均可做房主：** 同一份已安装的 Dusk Lake 客户端，既可单人游玩，也可点击「创建房间」成为房主，或点击「加入房间」进入朋友的湖畔。
- **房间上限：** 1 位房主 + 最多 3 位朋友（共 4 人）；默认仅邀请访问。房主可以管理访客、退出并结束房间。
- **同步的体验：** 同一地图上的玩家位置、朝向和角色外观；同一天气、季节与时间；木屋灯光、门、壁炉的共享交互；逐步扩展到一起坐下、在湖面共乘独木舟、摄影与共同寻找信件。
- **个人和公共数据分开：** 玩家自己的外观、照片与个人进度跟随玩家；木屋摆放、公共交互及世界状态属于房主世界存档。
- **单人模式永久保留：** 断网时仍可进入自己的私有湖畔，不依赖外部服务器。

## 2. 联机模式边界：不是所有电脑一直在线

首选架构为 **Listen Server（玩家托管的权威房主）**，不是每台机器相互平等地修改世界状态的全网状 P2P。所有游戏安装包都包含建立服务器和加入服务器的代码：

```text
你在自己的 PC 运行同一份安装版
    ├─ 单人游玩 → 加载本机世界存档
    ├─ 创建房间 → 本机既运行游戏客户端也运行权威会话服务器
    │                 ├─ 朋友 A 加入
    │                 ├─ 朋友 B 加入
    │                 └─ 朋友 C 加入
    └─ 加入房间 → 在朋友的服务器游玩；公共世界以朋友存档为准
```

房主退出，原房间默认关闭；其他人仍可用各自的电脑建立**新房间**。不存在“离线的朋友电脑仍然自动运营原房间”这种能力。

### 自动房主迁移是后期扩展，不属于首发前置

可选 Host Migration：房主离开或异常断线时，选择一个新房主、恢复最新世界快照、让其余玩家重连。需要状态备份、权限交接、候选房主选择、重连处理及冲突解决。**Godot ENet 不会自动提供迁移**。首发只要求稳定退出并告知“房主已离线”；以后有必要再追加不中断/短暂中断迁移。

后续若想无人在线时世界继续运行，需要独立常驻服务器或云托管；这不属于“每个人自己开房”的首版要求。

## 3. 安装包内必须包含什么

同一个 **Windows 安装包**应该内置以下内容（无需单独安装 Godot，也无需另下“服务端程序”）：

1. 游戏主菜单：**「单人游戏」「创建房间」「加入房间」**；本地/联机入口并列，联机不可用时单人不受影响。
2. `NetworkManager`、网络创建与加入界面、连接状态反馈、玩家生成、房主权限和退出／断线处理；联网模块同客户端一起打包。
3. 创建房间可设置人数上限和私有/受邀访问；加入房间支持 **IP/地址** 或后续实现的邀请途径，提供版本不匹配、房间已满、连接失败等清晰提示。
4. 客户端版本与资源兼容校验；角色独立身份与外观状态；动态房主权威世界快照；必要的断线／重新加入处理。
5. Windows 防火墙与网络设置说明；允许玩家自行授权联机监听端口，不应静默修改系统防火墙或承诺所有网络都能直连。
6. 安装完成后的启动、卸载和文件路径／存档位置说明；卸载是否保留个人存档必须明确。

**重要区分：内置游戏主机 ≠ 内置公网穿透服务。** 对于异地连接：
- 第一阶段通过 LAN、经授权的 Tailscale/类似虚拟局域网，或可用的公网地址 + UDP 端口转发连接。Tailscale 是双方**另行安装**的网络工具，不是 Dusk Lake 必须自带的游戏服务端。
- 公网 NAT/CGNAT 场景下直连可能失败。真正向普通用户承诺“无需网络配置的房间码一键加入”，需要额外的目录/信令与 Relay/打洞基础设施；**当前未开发，也不应把单纯的六位房间码当成联网保证**。
- 初始 ENet 服务端端口可从可配置的 UDP 端口开始（例如 24567），实际发行时统一配置并测试。

### 安装与发行为何需要独立验收

Windows 导出的 `.exe`、可能存在的 `.pck` 和所需依赖需完整打包。**安装包制作完成不意味着多人功能已可用**：必须通过两台真实电脑和跨网实测，并核验安装后监听 UDP、客户端同步与防火墙行为。与当前 M4 的单机导出验收分开记录，直到发行版本明确将联机定为交付范围。

## 4. 现有 Godot 工程的改造位置

按当前 [ARCHITECTURE](../docs/ARCHITECTURE.md) 中的约定扩展，不推翻原有地形和木屋。

| 现有组件 | 预计联机改造 | 重要约束 |
| --- | --- | --- |
| `scenes/main/Main.tscn` / `Main.gd` | 单一 Player 改为可动态生成的 Players；添加 Lobby UI、`MultiplayerSpawner` | `World` 和 `Cabin` 仍常驻同一空间；原单机模式仍可启动 |
| `FirstPersonController.gd` | 区分本地输入、服务器模拟与远端显示；只有本地角色使用第一人称相机 | 现有 `is_local_controlled` 和 `entity_id` 只是前置基础，不等于已同步 |
| `CharacterVisual` / M1.5 | 所有玩家需能看见他人模型、服饰和姿态；数据以稳定部件 ID 表示 | 捏脸和服装不直接作为整张网格每帧传输 |
| `NetworkManager.gd`（新增） | Godot `ENetMultiplayerPeer`、连接/断线信号、房主/访客身份、会话生命周期 | 玩家托管房间时本机兼任服务器 |
| `MultiplayerSpawner` / `MultiplayerSynchronizer` | 生成角色；同步位置、朝向和必要状态；插值减小抖动 | 优先服务器权威；避免客户端任意写权威状态 |
| `WorldState.gd` / `EventBus.gd` | 房主权威共享状态；变更事件转发；晚加入玩家接收完整快照 | `EventBus` 不替代状态存储；使用稳定 `uid`/`entity_id`/`zone_id` |
| `Interactable.gd` / 木门与生活交互 | 访客发送交互请求 → 房主检查距离/身份/权限 → 更新并广播结果 | 防止远距离开门、擅自编辑主人木屋 |
| `SaveManager.gd`（M4 待开发） | 房主世界存档与来访者个人资料分离；断线及重入恢复 | 版本化 `schema_version`、迁移、崩溃恢复 |

**网络负载原则：** 静态地形／森林／木屋模型各客户端自行加载，不逐帧通过网络发送；同步动态玩家、天气变化、交互与船只运动状态。

## 5. 分阶段实施计划（供 Claude Code / Codex）

每阶段须在独立分支完成并测试，不应一次实现全部：

1. **MP-0 — 两实例联机（LAN）**：`ENetMultiplayerPeer`、创建/加入/退出房间、局域网直连；保持纯单人原流程。
2. **MP-1 — 玩家可见与移动**：2–4 名玩家动态加入、房主权威移动（先可用，后改善延迟）、远端外观与朝向；服务器不把本机玩家误认为所有远端玩家。
3. **MP-2 — 共享状态与新玩家快照**：木屋门、灯、炉火及时间天气的权威状态；晚加入玩家拿到一致快照；权限与异常请求验证。
4. **MP-3 — 私有房间与可靠存档**：房间人数/身份、仅受邀访问、房主保存世界、访客个人状态、房主退出与断线重连策略。
5. **MP-4 — Windows 安装包联机验收**：同一安装版在 2 台以上 Windows 机器完成建房/加入；在目标网络环境下跨网络测试；安装包内容、版本一致性、存档与防火墙说明均核验。**这是带联机功能的发行版本必须完成的交付门槛。**
6. **MP-5 — 后期扩展（非首发阻塞）**：自动房主迁移、房间码目录服务／Relay、朋友共乘独木舟及空间语音等，根据玩家需求再做。

## 6. 发行验收清单

- [ ] 一份 Windows 安装包支持三入口，任意两名玩家可交换房主与访客角色；**不要求另装 Godot 或独立服务端程序**。
- [ ] 首次安装、升级安装和离线单人正常；联网失败不导致存档丢失。
- [ ] 在两台不同 Windows 电脑上实现连接、断开和二次加入；最多 4 人，人数上限有效。
- [ ] 每位玩家只控制自己的镜头和输入；其他人能看到位置、朝向和服装。
- [ ] 门、灯、壁炉和世界时间／天气在所有客户端一致；新加入的玩家不会看到默认错误状态。
- [ ] 普通访客不能绕过房主权限修改木屋持久摆设；服务器验证交互距离、会话身份和非法状态。
- [ ] 房主退出时客户端收到清晰提示并回到安全菜单；房主世界记录不被其他客户端覆盖。
- [ ] 在 LAN 和至少一个实际异地连接方案下测试；明确 NAT/防火墙局限和使用说明；**不虚称所有人都能直接使用房间码连接**。
- [ ] 版本号一致性、断线重入、船只上下船（启用后）、存档版本升级与单机 QA-01/02/10 回归通过。
- [ ] Windows 导出/安装器构建、许可证审计、实际机器性能测试和外部素材授权核验均留有记录。

## 7. 范围与归档

本文件明确用户希望**未来正式安装版附带任意玩家开房的联机能力**。原有 M5 规划中的多人仍未开发，现阶段仅增加创意及发行要求，不自动修改 [docs/DEVELOPMENT_SPEC.md](../docs/DEVELOPMENT_SPEC.md)，也不将 MP-0–MP-5 标记为完成。

若将它确立为 **第一版发行的阻塞项**，需要正式修订里程碑和发行验收；若先给朋友单机内测版，可以单独标记为预览构建，避免与最终正式安装版混淆。
