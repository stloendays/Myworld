## 推荐交付节奏

1. **验证现有 M0/M1**：保持原自动测试与室内外场景连续性，不动坐标事实源。
2. **核心小体验（M3/M4 奠基后）**：点灯、炉火、沙发、收音机，并保存互动状态。
3. **非强制故事**：3 封信件、收集册、1 个温柔的结尾奖励。
4. **摄影实验**：在测试分支跑通 Lente 的进入、截图、退出，以及与 PauseMenu 相容；正式集成前确定版本。
5. **舟行探索**：先做可上下船、两处靠泊、永不困在深水的灰盒；最后添加船模、尾波和声效。
6. **更远的版本**：有需求后才引入 Dialogue Manager 4 和 Beehave；不要为了它们强行提前实现 NPC 系统。

## 安装包内置多人联机（2026-10-21 新增产品方向）

- **目标：** 面向朋友的正式 Windows 安装版本身支持「单人 / 创建房间 / 加入房间」，任何安装游戏的朋友都能用自己的电脑作为 Listen Server，1 房最多 4 人。无需单独分发服务端可执行文件。
- **实施前提：** M1.5 完成可见的角色外观、M4 存档设计明确、联网逻辑保留现有世界坐标与稳定 ID。当前 `FirstPersonController.is_local_controlled` 只是预留接口，并非联机完成。
- **必须验收才可声称安装版支持多人：** MP-0 LAN 连接 → MP-1 玩家移动/外观 → MP-2 世界状态/晚加入快照 → MP-3 私有房间/权限/存档 → **MP-4 实际 Windows 安装包双机 + 异地网络验证**。
- **后置：** MP-5 自动房主迁移、目录/房间码 Relay 服务、常驻服务器和复杂双人玩法不阻塞首批联机发行；房主退出默认关闭房间。
- **网络现实：** LAN、虚拟局域网（如 Tailscale）、公网地址+UDP 端口映射须各自说明；异地使用虚拟局域网可能需要用户额外安装网络工具；没有打洞或 Relay 服务时不能承诺随处输入房间码即可连接。
- **发行范围决策：** 开发过程可有单机测试构建，但面向朋友正式分发的目标安装版应将内置多人功能作为发行检查项。改变原规格里 M5 的后期性质时，须显式修订 [正式需求](../docs/DEVELOPMENT_SPEC.md) 和版本里程碑。

完整方案、代码适配点与具体测试见 [multiplayer-player-hosted.md](multiplayer-player-hosted.md)。**这仍是待实施计划。**
