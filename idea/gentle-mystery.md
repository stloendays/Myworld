# 创意 02｜神秘信件与温柔剧情（Gentle Mystery）

**状态：待评估／尚未实施。** 这是一条可以完全忽略的叙事支线，不应该变成强制任务链。

## 核心情绪

玩家在自己的湖畔小世界里，偶尔找到陌生人留下的信件、旧明信片、藏在书里的便条。故事有一点谜团，但没有恐怖、战斗或限时失败。核心主题是 **记忆、善意、告别与重新相遇**。

## 第一则故事原型：《寄往湖的信》

*创意方向，非最终剧情。*

- **信件 A｜木屋旧书**：夹在书中的纸条提到有人每年傍晚来湖边等待一封回信。玩家可以选择收藏或放回。
- **信件 B｜码头的旧木盒**：提到岸对面的一个地点和一本从未归还的自然笔记。可给出简短、不过分显眼的线索。
- **信件 C｜隐秘湖湾**：找到最后一封信与几张湖畔旧照片，发现原来有人一直在记录四季变迁、为未来路过的旅人留下祝福。
- **结尾**：木屋出现一本新的相册／一张装饰画。玩家可继续自由探索；不会弹出通关或强制结束。

## 玩法原则

- 用环境叙事带动探索，不设计密集地图图标；线索可重复查看，不会永久错过。
- 支持跳过、按自己顺序读、不强制一次找完；完成反馈是温暖的小物件，而非伤害性的奖励机制。
- 字号可调，信件长文可逐段翻页；键盘／鼠标可浏览并退出；首次阅读不覆盖玩家正常存档。
- 与未来 NPC 对话兼容，但在第一版 **完全可以不用 NPC 或对话插件**。

## 技术落点

- 信件定义建议为数据文件（例如 `data/story/letters.json`），至少包含稳定 `letter_id`、标题、文本、线索依赖、触发条件和解锁内容；不要把整篇文本硬编码在节点脚本里。
- 现有 `InteractionSystem` 可复用，信件物体有独立稳定 `uid`；读过的 `letter_id`、收藏状态记录进 `WorldState.flags`，由 M4 `SaveManager` 持久化。
- 线索地点需要先由 `data/world/world_layout.json` 定义，位置不能直接散落在脚本里。
- 日后需要多选项分支对话时再评估 [Dialogue Manager 4](https://github.com/nathanhoad/godot_dialogue_manager)，并与简单信件 UI 分开。

## MVP 验收

- [ ] 至少 3 封信可经现有交互系统拾取、阅读、关闭并重复查看。
- [ ] 可依据线索发现下一封信，但不要求固定线性顺序。
- [ ] 玩家读过的信件与完成状态在存档重开后完全一致。
- [ ] 文本可读、UI 不抢占角色鼠标、退出阅读返回第一人称。
- [ ] 线索地点与其他物体不重叠；不影响现有 QA-01/02 室内外连续验证。
