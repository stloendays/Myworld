# 内存与卡顿优化（2026-10-22）

起因：用户反馈“运行起来会很卡”。实测配置就是用户自己的设置：2560×1600 全屏、高画质、RTX 5060 Laptop（8 GB 显存）、15 GB 内存。

## 1. 先测清楚

新增 `devtools/MemProbe.tscn`：加载计时 → 记录内存 / 显存 / 进程占用 → 沿一条走遍全图的路线（出生点、木屋室内、北部林道、雪山、码头、泳池馆、地下水族馆、仙境、南部草甸）以 7 m/s 移动，途中切四种天气预设 → 统计帧时分布和超过 33 ms 的卡顿帧。

```
Godot_console.exe --path . --resolution 1600x900 res://devtools/MemProbe.tscn
```

结论：

| 发现 | 数据 |
|---|---|
| 真正让人觉得卡的情况 | 同时跑其他吃显卡的程序时。实测时另一个 TTS 进程占了约 6 GB 显存，游戏再要 1–1.9 GB 就超出 8 GB，显存换页，平均帧时从 9 ms 变成 90 ms |
| 外部贴图无压缩、无 mipmap | 57 张 1k 贴图按无损导入，每张 4 MB 显存且没有 mipmap（远处闪烁、带宽浪费） |
| 启动 15.6 s | 地被 4.7 s、地形 2.8 s、树林 1.3 s：每个候选点要算好几次 `height_at`，而它每次都在查 JSON 字典（17 µs / 次） |
| 湖面反射重拍尖峰 | 每次太阳高度变化 2.5° 就把湖面探针整套重拍一次（6 个面一帧画完，带阴影），那一帧约 24 ms |
| 定时全树搜索 | `PerformanceDirector` 每 5 秒在 7000 个节点里找灯，每次 3.4–5 ms |
| 换季 | 树和地被几万个实例逐个 `set_instance_color` |
| 脚本 | 逐个关掉每类脚本测帧时，单项都在 1 ms 以内，不是瓶颈 |

## 2. 改了什么

| 做法 | 实现 |
|---|---|
| 贴图显存压缩 + mipmap | 57 张 Poly Haven 贴图改为 VRAM 压缩导入（颜色、粗糙度 BC1，法线 BC5）并生成 mipmap：每张 4 MB → 0.7 / 1.4 MB（含 mipmap）。地形五层贴图数组直接用压缩数据，不再解压成 RGBA8 |
| 画质档位里的显存项 | 高画质：MSAA 2× 换 SMAA（2560×1600 下省约 34 MB，GPU 带宽也更省）、点光源阴影图集 4096 → 2048；中画质 SMAA + 天空辐照 128；低画质 FXAA + 阴影图集 1024 + 天空辐照 128；极高画质保持 MSAA 2× |
| 地形高度函数 | `WorldTerrain` 第一次调用时把山、平台、岛、基坑、湖参数解析成定长数组：17 µs → 5.4 µs，2 万个随机点结果逐位一致 |
| 植被规则 | `Vegetation` 同样缓存空地、林区、稀疏区、建筑占地：林地密度 7.3 → 2.2 µs |
| 地被摆放提前淘汰 | 适宜度只可能是 0 或“种类系数”（草甸距离、林地密度），先用它淘汰随机点，结果不变，草甸的 2 万多个候选点大多在这一步就结束 |
| MultiMesh 整块写入 | `ForestBuilder.fill_instances` 一次写入全部实例，数组留在 meta 里；换季只改颜色再整块上传 |
| 模型后台并行读取 | `Main._enter_tree` 先对树林、地被要用的几十个 Kenney 模型发起后台读取 |
| 湖面反射重拍不画阴影 | 重拍那一帧 24 ms → 17 ms；远岸倒影里看不出差别 |
| 灯的淡出改成事件驱动 | 启动扫一次，之后新加入的灯在 `node_added` 时处理，去掉每 5 秒一次的全树搜索 |

树木 / 岩石 2075 个、地被 6742 个实例的摆放与改前逐位一致（校验和相同）。

## 3. 结果

`MemProbe`，2560×1600 全屏、高画质，同一台机器空闲时：

| 项 | 改前 | 改后 |
|---|---|---|
| 进入世界（到第一帧） | 15.6 s | 7.6 s |
| 各节点 `_ready` 合计 | 13.9 s | 4.7 s |
| Godot 显存计数 | 1040 MB | 802 MB |
| 其中贴图与渲染缓冲 | 915 MB | 685 MB |
| nvidia-smi 看到的游戏实际显存 | 约 1.9 GB | 约 1.6 GB |
| 湖面反射重拍那一帧 | 24 ms | 17 ms |
| 绕图一圈帧时 p99 | 15.8 ms | 14.4 ms |

- 进程内存（任务管理器约 1.0 GB）基本没变：无窗口运行时整个进程只占 260 MB，其余都是显卡驱动侧，不随游戏显存或分辨率变化。
- 不限帧率的帧率在连续测试中波动 ±20% 以上（笔记本温度），上表不放帧率。
- 剩下最大的一块是 2560×1600 下的内部渲染缓冲（渲染比例 50% 时还能少约 220 MB）。如果和别的大程序一起开，把设置 → 画面 → 渲染比例调到 75% 最有效。

## 4. 自动检查
